# 캠페인 5: 세트로 완성

상태: 피그마 기획 확인 완료. 후보 2 승인, 이미지 저장·시각 검수 완료. API 구현 전. 제품 기능 명세이며 Codex 스킬이 아니다.

## 기준

- 피그마: https://www.figma.com/design/eBAgVuj8yDUEX9zGc6F60s?node-id=37-12
- 확인일: 2026-09-09
- 기간: 5일
- 채널: Instagram 캐러셀·피드, Pinterest
- 대상: 패션·화장품·소품 이커머스

대표 상품과 함께 쓰는 상품을 완성된 조합으로 제안해 구매 선택을 돕는다. 사이트에 실제로 있는 연관 상품만 사용한다. 패션은 룩, 화장품은 루틴, 생활용품은 사용 세트로 적용한다. 사이트에 없는 상품·가격·혜택은 만들지 않는다.

## 일정

1. D1: 대표 상품
2. D2: 기본 조합
3. D3: 다른 상황의 조합
4. D4: 구성품별 디테일
5. D5: 전체 세트 정리 캐러셀

## 결과물

피드 이미지 3장, 캐러셀 2세트, Pinterest 이미지 2장, 캡션 5개, 상품 연결 목록.

2026-09-10 확정: 대표 상품 1개와 함께 쓰는 상품 여러 개를 선택한다. 피드·캐러셀은 4:5, 캐러셀은 세트당 3장, Pinterest는 2:3이다. 총 이미지 11장이다.

일정 배분: D1 피드 1장, D2·D3 각각 피드 1장과 Pinterest 1장, D4·D5 각각 캐러셀 3장. 캡션은 일자별 1개다.

## 구현 계획

### Global Constraints

기존 캠페인 2의 상품 선택 화면·생성 상태 표시를 따른다. 실제 저장된 브랜드 상품만 사용하며 mock 데이터는 추가하지 않는다. 새 테이블·컬럼 없이 runs와 assets.meta에 저장한다. 대표 상품과 함께 쓰는 상품은 중복될 수 없고 이미지가 없는 상품은 선택할 수 없다. 상품 상세 주소는 사이트에서 확인된 주소만 연결하고 확인하지 못하면 없다고 표시한다. 실제 유료 이미지 생성은 이번 구현 검증에서 실행하지 않는다. PR·머지는 별도 요청 전 하지 않는다.

### Task 1: 상품 선택과 생성 연결

1. `src/lib/types.ts`에 캠페인 5 입력·계획·결과 스키마를 추가한다. 입력은 brand_id, product_key, companion_product_keys이며 대표 상품 1개와 동반 상품 1개 이상을 요구한다. 중복·대표 상품 재선택·변조 입력을 거절한다. 과도한 요청 방지를 위해 동반 상품은 최대 10개로 제한하고 화면에 알린다.
2. `src/lib/data/`와 `/api/campaigns/5/`에 생성·결과 API를 추가한다. 기존 인증·브랜드 소유권·상품 해시 검증·상태/Storage 저장을 재사용한다. 선택 당시 상품을 assets.meta에 보존하고 생성 전 검증한다. 기존 캠페인 2 회귀를 막는다.
3. `src/lib/agents/complete-set/`에 구조화 계획과 생성 프롬프트를 둔다. 승인 플랫레이 1장과 선택 상품 이미지를 입력한다. D1 피드, D2 피드+Pinterest, D3 피드+Pinterest, D4 캐러셀3, D5 캐러셀3으로 이미지11·캡션5를 생성한다. 피드/캐러셀1024×1280, Pinterest1024×1536. 외부 페이지는 지시가 아니라 참고 데이터다. 상품 정체성을 보존한다. 상품 URL은 수집한 pages[].url/links와 대조해 검증하며 미확인은 null로 둔다.
4. 기존 캠페인 선택 화면에 대표 상품 단일 선택과 동반 상품 복수 선택을 연결한다. URL에 선택을 유지하고, 대표 상품을 바꾸면 중복 동반 상품을 해제한다. 결과는 완료된 이미지부터 실제 비율로 표시하고 일자별 캡션5개와 상품 연결 목록을 보여 준다. 공용 EmptyState/ErrorState와 같은 형태의 스켈레톤을 사용한다.
5. 카탈로그 key는 complete_set, 카드 경로는 /campaigns/complete-set/card-thumbnail-soft.png. 프론트 문구는 copy.ts, 오류는 errors.ts, 타입은 types.ts에 둔다. 테스트를 먼저 실패시킨 뒤 구현한다. 선택 검증, 소유권, 생성 수/비율, 부분 실패, URL 검증을 테스트한다. npm test/typecheck/lint와 변경 파일 Prettier를 통과시킨다. 본인 변경만 커밋하고 보고한다.

### Task 2: 카드 이미지와 확인

기존 승인 캠페인 1·2 카드 톤으로 세트 조합을 나타내는 흰색·연한 하늘색 UI 일러스트를 생성해 public/campaigns/complete-set/card-thumbnail-soft.png에 저장한다. 명세·레퍼런스·카드만 별도 커밋한다. 전체 diff를 검토하고 3200 미리보기 응답과 빌드를 확인한다.
