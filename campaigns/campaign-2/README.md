# 캠페인 2: 한 상품, 세 장면

상태: 레퍼런스 후보 제시. 사용자 선택 후 파일 저장과 에이전트 API 구현을 진행한다.

## 기준

- 피그마: [02 한 상품, 세 장면](https://www.figma.com/design/eBAgVuj8yDUEX9zGc6F60s?node-id=33-3)
- 확인일: 2026-09-09
- 대상: 패션·화장품·소품 이커머스
- 기간: 5일
- 채널: Instagram 피드·캐러셀·스토리

상품은 봤지만 언제 어디서 어떻게 쓸지 떠오르지 않는 사람에게 구매 후 사용 모습을 보여 준다. 같은 대표 상품을 유지하고 고객과 상품에 맞는 세 장면을 바꾼다. 출근·주말 같은 장면을 고정 템플릿으로 강제하지 않는다.

## 일정과 산출물

| 일자 | 내용              | 결과물                                       |
| ---- | ----------------- | -------------------------------------------- |
| D1   | 상품 단독 소개    | 피드 이미지 1장, 캡션 1개                    |
| D2   | 첫 사용 장면      | 피드 이미지 1장, 스토리 이미지 1장, 캡션 1개 |
| D3   | 두 번째 사용 장면 | 피드 이미지 1장, 스토리 이미지 1장, 캡션 1개 |
| D4   | 세 번째 사용 장면 | 피드 이미지 1장, 스토리 이미지 1장, 캡션 1개 |
| D5   | 세 장면 정리      | 캐러셀 1세트, 캡션 1개                       |

총 피드 4장, 스토리 3장, 캐러셀 1세트, 캡션 5개, 업로드 순서. 캐러셀 장수와 피드 비율은 레퍼런스를 고른 뒤 확정한다.

## 레퍼런스 후보

아래는 미승인 후보다. 선택된 자료만 `reference/campaigns/campaign-2/`에 파일로 저장한다.

1. [V by Very — Fashion Three Style](https://www.bauermedia.co.uk/case-studies/fashion-three-style/): 피그마의 기획 근거. 대표 아이템을 유지하며 여러 스타일을 제시하는 방식.
2. [Dida Ritchie — One Bag, Three Ways](https://www.didaritchie.com/blogs/the-edit/one-bag-three-ways-2): 같은 가방을 세 가지 룩으로 제안하는 편집 구성.
3. [JS Colore — One Bag, Three Different Looks](https://www.jscolore.com/blog/icerik/one-bag-three-different-looks): 같은 토트백을 다른 상황과 스타일링으로 보여 주는 구성.

사용자는 여러 후보를 선택하거나 다른 레퍼런스 링크를 제공할 수 있다. 선택 전 승인된 레퍼런스는 0개다.

## 후속 에이전트 API

입력은 저장된 브랜드 프로필, 사용자가 고른 대표 상품, 현재 사이트의 확인된 사실, 승인된 내부 레퍼런스다. 대표 상품이 정해지지 않았으면 사용자에게 선택받는다.

에이전트는 상품의 형태·색·로고 등 정체성을 유지하면서 세 장면과 카피를 구성한다. 사이트에 없는 특징·효능·가격·할인·후기를 만들지 않는다. 결과는 구조화 출력으로 검증한다.

API 경로는 캠페인 1 패턴의 `/api/campaigns/2/runs`와 개별 run 조회를 따른다. 구체적인 요청·응답 타입과 campaign key는 레퍼런스 선택 이후 PLAN에 반영하고 구현한다.

## 카드와 상세 등록

레퍼런스 선택 이후 기존 카드 톤에 맞는 캠페인 소개 이미지를 AI로 생성한다. 대표 상품 하나와 세 장면의 관계가 작은 카드에서도 읽혀야 한다.

이미지는 Supabase Storage에 저장하고 이름·목적·기간·채널·일정·산출물·필수 입력과 함께 서버 정의로 제공한다. 승인된 레퍼런스 자체를 카드 이미지로 사용하지 않는다.
