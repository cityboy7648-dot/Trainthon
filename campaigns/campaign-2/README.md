## 후속 에이전트 API

입력은 저장된 브랜드 프로필, 사용자가 고른 대표 상품, 현재 사이트의 확인된 사실, 승인된 내부 레퍼런스다. 대표 상품이 정해지지 않았으면 사용자에게 선택받는다.

에이전트는 상품의 형태·색·로고 등 정체성을 유지하면서 세 장면과 카피를 구성한다. 사이트에 없는 특징·효능·가격·할인·후기를 만들지 않는다. 결과는 구조화 출력으로 검증한다.

캠페인 key는 `one_product_three_scenes`다.

### 상품 선택

캠페인 선택 후 같은 화면 아래에 상품 질문을 표시한다. 저장된 브랜드의 상품 사진·이름·가격을 스크롤 가능한 목록으로 보여 준다. 한 상품만 선택하며 선택 전 생성 버튼은 비활성화한다. 상품이 없거나 조회에 실패하면 빈 상태 또는 오류와 재시도를 표시한다. 동일 상품을 유지하기 위해 이미지 없는 상품은 생성할 수 없다.

`GET /api/campaigns/2/products?source_url=...`: 로그인한 사용자의 해당 브랜드와 상품 목록을 반환한다. source_url 생략 시 가장 최근 브랜드를 사용한다.

`POST /api/campaigns/2/runs` 요청: `{ brand_id, product_key }`. 응답: `{ run_id }` (202).

product_key는 서버가 상품 내용으로 만든 SHA-256 식별자다. 서버는 소유권과 최신 상품 목록을 다시 확인한다. 상품 내용이 바뀌면 재선택을 요청하며, 클라이언트가 보낸 가격·이미지·프롬프트를 생성 근거로 쓰지 않는다. 확정 상품 스냅샷은 기존 assets.meta에 저장한다.

`GET /api/campaigns/2/runs/{run_id}`: run 상태와 이미지 10장의 상태·이미지 URL·일자·포맷·캡션·오류를 반환한다. 결과 화면은 4초마다 조회하며 실제 DB 상태로만 진행률을 표시한다.

승인 레퍼런스 4장과 선택 상품 이미지를 기획 및 이미지 생성에 전달한다. 기획은 gpt-5.5 구조화 출력, 이미지는 gpt-image-2를 사용한다. 피드는 1024×1280, 스토리는 1152×2048로 요청한다.

실패한 항목은 실패 상태로 남기고, 다시 만들기는 새 run과 새 assets를 만든다. 생성 요청은 Next.js after에서 실행하며 최대 800초다. 중단된 작업이 계속 생성 중으로 남지 않도록 12분이 지난 미완료 작업은 조회 시 실패 처리한다. 영구 작업 큐는 아직 연결하지 않았다.

## 카드와 상세 등록

레퍼런스 선택 이후 기존 카드 톤에 맞는 캠페인 소개 이미지를 AI로 생성한다. 대표 상품 하나와 세 장면의 관계가 작은 카드에서도 읽혀야 한다.

이미지는 Supabase Storage에 저장하고 이름·목적·기간·채널·일정·산출물·필수 입력과 함께 서버 정의로 제공한다. 승인된 레퍼런스 자체를 카드 이미지로 사용하지 않는다.
