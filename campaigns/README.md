# 캠페인 제작 명세

이 문서는 제품 기능의 제작 절차다. Codex 스킬이나 설치형 에이전트 스킬이 아니다.

## 제작 순서

1. [피그마 캠페인 후보군](https://www.figma.com/design/eBAgVuj8yDUEX9zGc6F60s?node-id=4-2)에서 번호, 이름, 목적, 기간, 채널, 산출물을 확인한다. 배열 순서나 오래된 목록으로 번호를 추측하지 않는다. 해당 노드 URL을 개별 명세에 기록하고 PLAN과 다르면 구현 전에 맞춘다.
2. 캠페인 1처럼 실제 사례와 시각 레퍼런스 후보를 제시한다. 사용자가 고른 자료만 승인된 레퍼런스로 확정한다.
3. 승인된 파일을 `reference/campaigns/campaign-N/`에 저장하고 `source.txt`에 원문 URL, 이미지 URL, 파일명, 선택 내역을 기록한다. 후보는 개별 README에 따로 적으며 미승인 파일을 에이전트 입력에 넣지 않는다.
4. 승인된 레퍼런스와 개별 명세를 기준으로 에이전트 API를 구현한다. 브랜드 프로필, 대표 상품, 사이트에서 확인한 사실과 사용자 입력으로 기획한다. 미정 값은 추측하지 않는다.
5. 기존 캠페인 카드의 비율·구도·색감에 맞춰 AI로 대표 이미지를 만든다. 캠페인 상세와 이미지 URL을 서버 정의에 등록하고 카드 → 상세 → 입력 → 생성 결과 연결을 검증한다.

## 구현 위치

| 내용                                    | 위치                                          |
| --------------------------------------- | --------------------------------------------- |
| 공통 제작 절차                          | `campaigns/README.md`                         |
| 번호별 목적·입력·일정·산출물·API 명세   | `campaigns/campaign-N/README.md`              |
| 승인된 내부 레퍼런스와 출처             | `reference/campaigns/campaign-N/`             |
| 캠페인 정의                             | `src/definitions/` — 번호와 고유 key를 명시   |
| 서버 데이터 조회·저장 및 카드/상세 제공 | `src/lib/data/`                               |
| 에이전트 실행 및 프롬프트               | `src/lib/agents/<campaign-key>/`, `prompt.ts` |
| API 라우트                              | `src/app/api/campaigns/N/runs/` — 요청 연결만 |
| 생성 이미지 및 공개 카드 이미지         | Supabase Storage, 서버 정의에 URL 기록        |

카드와 상세는 같은 서버 정의를 사용한다. 이름·목표·기간·채널·일정·산출물·필수 입력·대표 이미지가 서로 달라지지 않게 한다. 내부 레퍼런스와 사례 원문은 제품 화면에 노출하지 않는다. AI 카드 이미지는 캠페인 소개용이며 실제 고객의 생성 결과로 표시하지 않는다.

API는 프로젝트의 인증·소유권 확인, zod 검증, provider 경계, runs/assets 상태 및 비용 귀속 규칙을 따른다. 새 DB 테이블을 임의로 만들지 않는다.
